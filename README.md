# 製造業 手法アドバイザー

やりたいことを日本語で入力すると、要因効果分析・応答曲面法・逐次最適化・オンライン学習から、**最初に使う手法を1つ**提案します。推奨度（高／中／低）、着手方法、適用条件、追加確認事項を表示します。

**学習済みモデルはGit管理対象外です。** `setup.cmd` の実行時にHugging Faceの配布元から自動取得します。モデルの利用条件は配布元で確認してください。

## 動作環境

- Windows / Python 3.12（Tkinterを含む）。
- セットアップではLaya 0.4.11 / PyTorch 2.14.1 CPU版を導入します。
- CPUで実行します。GPU設定やAPIキーは不要です。
- セットアップ後の推論はローカルで行い、相談内容を外部APIへ送信しません。
- 「結果をJSONで保存」で、入力・結果・モデル生出力・選定根拠を保存できます。
- 入力は任意の補足を含め1600文字以内です。

## セットアップと起動

1. リポジトリをクローンまたはダウンロードします。
2. Python 3.12をインストールし、`py -3.12` で実行できる状態にします。
3. アプリのフォルダーにある `setup.cmd` を実行します。専用の仮想環境を作成し、依存パッケージの導入とモデルのダウンロードを行います。
4. 完了後、`start.cmd` をダブルクリックします。
5. やりたいことを入力し、「おすすめを判定」を押します。入力例も選べます。

初回セットアップにはネットワーク接続とディスク空き容量が必要です。仮想環境の `.venv` は移動用ではないため、別のPCや別フォルダーでは再作成してください。モデルは初回判定時にメモリへ読み込み、以後は再利用します。

起動に失敗した場合はターミナルにエラーを表示して停止します。詳細は同じフォルダーの `startup.log` に保存されます（起動ごとに上書き）。`start.cmd` と `setup.cmd` はWindows用のCRLF改行で保存してください。

`requirements.txt` はLaya本体のバージョン指定です。モデルのリビジョンはセットアップ時に `model_revision.txt` に保存し、通常起動では保存済みのモデルだけを読み込みます。`download_model.py` を再実行すると取得時点のモデルに更新するため、更新後は用途に合った判定になるか確認してください。

### モデルのサイズと取得元

このアプリは、Layaの**多言語モデル（`multilingual`）**を使用します。PythonパッケージのLaya本体とは別に、学習済みモデルとトークナイザーをダウンロードします。容量の目安は次のとおりです。

| 内容 | サイズ |
|---|---|
| モデル重み `model.safetensors` | 約644 MB（約614 MiB） |
| トークナイザー `tokenizer.json` | 約34 MB |
| 設定ファイルを含むモデル関連ファイルの合計 | 約678 MB（約647 MiB） |

ここでMBは1,000,000 bytes、MiBは1,048,576 bytesです。モデルのリビジョンによってサイズは変わる可能性があります。別途、Python仮想環境・PyTorchなどの依存パッケージやダウンロード用キャッシュの空き容量も必要です。このファイル容量は、推論時のメモリ使用量とは異なります。

取得元は **Hugging Face Hub** の公式リポジトリ [`convaiinnovations/laya`](https://huggingface.co/convaiinnovations/laya/tree/main/multilingual) です。`setup.cmd` が依存パッケージの導入後に `download_model.py` を実行し、次の処理で配布元から直接取得します。通常のアプリ起動時にはダウンロードしません。

```python
from huggingface_hub import snapshot_download

path = snapshot_download(
    "convaiinnovations/laya",
    allow_patterns=["multilingual/*"],
)
```

`allow_patterns` により、リポジトリの多言語モデル配下だけを取得します。英語用など他のモデルは取得しません。

モデルだけを取得・再取得する場合は、アプリのフォルダーで次を実行してください。初回セットアップでは `setup.cmd` が実行するため、別途実行する必要はありません。

```powershell
.\.venv\Scripts\python.exe download_model.py
```

保存先は既定でアプリ内の `models/hub/` です。取得したモデルは次の構造で管理し、ダウンロード後にリビジョンIDを `model_revision.txt` に記録します。

```text
models/hub/models--convaiinnovations--laya/
  blobs/                           # 実データを保管するキャッシュ
  snapshots/<リビジョンID>/multilingual/
    model.safetensors
    rl_agent_config.json
    encoder/config.json
    tokenizer/tokenizer.json
    tokenizer/tokenizer_config.json
```

`snapshots` 配下はキャッシュ内の実データを参照する場合があります。容量を数える際に `blobs` と参照先のファイルを二重に加算しないでください。アプリ起動時は保存済みリビジョンのローカルモデルを読み込み、モデル取得のために毎回Hugging Faceへ接続する処理は行いません。

## コマンドライン

```powershell
.\.venv\Scripts\python.exe advisor.py "影響度の大きいパラメーターを特定したい"
.\.venv\Scripts\python.exe advisor.py "設計条件を探索したい" --context "CAEは1回8時間。結果を見て次の条件を決められる" --json
```

## 選定方法

本プログラムは、**Layaによる文章の判定と、Pythonに記述した選定ルールを組み合わせて**結果を出します。1件の相談に対してLayaを2回呼び出します。最終的な手法の決定、推奨度の表示調整、説明文の組み立てはPython側が担当します。

### 全体の流れと担当

| 順序 | 処理 | 担当 | 実装箇所（`advisor.py`） |
|---|---|---|---|
| 1 | 入力と任意の補足を結合し、文字数・トークン数を確認 | Python。トークン数の計測にはモデル付属のトークナイザーを使用 | `Advisor.recommend()` の冒頭 |
| 2 | 4択と、合格範囲・継続更新に関する2つの目的を判定 | **Laya：1回目の推論** | 最初の `agent.predict()` |
| 3 | 目的の判定値にしきい値を適用して候補を変更 | Pythonの条件分岐 | `update` / `window` の `noul` を確認する部分 |
| 4 | 入力中の明示的な目的を文字パターンで調べ、該当すれば候補を上書き | **Laya以外：Pythonの正規表現と優先規則** | `explicit_purpose()` とその呼び出し部分 |
| 5 | ここで選んだ1手法の適切さを3段階で評価 | **Laya：2回目の推論** | `fit` を渡す2番目の `agent.predict()` |
| 6 | スコアを高・中・低に変換し、不確実性や情報不足に応じて調整 | **Laya以外：Pythonのしきい値・表示規則** | `fit_value` から戻り値を作るまで |
| 7 | 手法ごとの説明・進め方・確認事項を表示 | **Laya以外：事前に記述した定型文** | `METHODS` と `render()` |

Layaは `Advisor.load()` で、保存済みの公式多言語モデルを `laya.load(..., device="cpu")` により読み込みます。このアプリで製造業向けの追加学習やモデル重みの更新は行っていません。選択肢の説明や評価基準は、推論時に毎回渡しています。

### 1回目のLaya：手法の4択と目的の判定

入力文に任意の補足を付けた同じ文章（`state`）を渡し、次の3問をまとめて判定します。

| 質問ID | Layaの判定形式 | 問う内容 | 主な出力 |
|---|---|---|---|
| `method` | `choice` | 目的と制約から、最初に使う手法を4つのうち1つ選ぶ | 選択結果 `choice`、4候補の `probabilities` |
| `window` | `noul` | 合格する条件の範囲・プロセスウィンドウを明確化したい相談か | 肯定側の判定値 `noul`（0〜1） |
| `update` | `noul` | 品質実績で予測モデルを継続更新し、摩耗や材料変化に追従したい相談か | 肯定側の判定値 `noul`（0〜1） |

4択では、手法名に加えて `METHODS` に記述した各手法の適用目的を渡します。入力に対応する選択肢をLayaが評価します。この時点の `method.choice` は、その後の処理で変更される可能性がある候補です。

### Layaの出力から、Pythonが手法を決める順序

処理順は次のとおりです。**後の処理による上書きが優先**されます。

1. Layaの `method.choice` を最初の候補とします。
2. Layaの `update.noul >= 0.90` なら「オンライン学習」に変更します。
3. 2に該当せず、`window.noul >= 0.90` なら「応答曲面法」に変更します。両方が0.90以上なら、この段階ではオンライン学習を優先します。
4. `explicit_purpose()` が入力から目的を検出した場合は、その結果で上書きします。**この規則は、Layaの4択結果にも、2・3の結果にも優先します。**

0.90という値の設定と、比較・上書きの処理はPython側の設計です。Layaが自分でこの優先順位を決めているわけではありません。また、0.90は製造業データで校正した値ではなく、実装時に設定した暫定値です。

### Laya以外の処理：明示目的の正規表現ルール

`explicit_purpose()` は、入力中に特定の語句やその並びがあるかをPythonの `re` で確認します。ここではLayaを呼び出しません。検出は次の順で行い、**最初に一致した1つを返します**。

| 優先順位 | 検出する表現の例 | 選ぶ手法 |
|---|---|---|
| 1 | 「継続…更新」「モデル…更新」などに加え、「追従」「変化」「摩耗」「毎時」などがある | オンライン学習 |
| 2 | 「影響…特定」「効果…調べ」「どの…効く」「因子…絞り込」など | 要因効果分析 |
| 3 | 「プロセスウィンドウ」「合格…範囲」「公差…領域」「二次式」「近似式」など | 応答曲面法 |
| 4 | 「結果…次」「次…実験」「高価…試験」「試験…少しずつ」など | 逐次最適化 |

表の「…」は任意の長さではなく、コードで定めた文字数以内の間隔を表します。正確な語句と間隔は `explicit_purpose()` の正規表現で確認できます。

照合の前に句点・疑問符・改行などで入力を区切り、「不要」「しない」「必要ない」「せず」「望まない」を含む部分を目的ルールの対象から除きます。例えば「継続更新は不要」を、継続更新したい目的として拾うことを避ける処理です。これは文字パターンによる簡易処理であり、否定の意味やかかる範囲を完全に解釈するものではありません。除外はこの目的ルールにだけ適用され、Layaには元の文章を渡します。

複数の目的が書かれた場合も、上表の固定優先順位で1つに決まることがあります。利用者の目的間の重要度を自動で推定しているわけではありません。

### 2回目のLaya：選ばれた手法の適切さを評価

手法を1つに決めた後、同じ入力文と、その手法の適用目的・注意点をLayaに渡します。質問IDは `fit`、形式は `score` です。**ここでは手法を選び直さず、選定済みの1手法だけを評価します。**

評価基準は次の3段階です。

| 段階 | Layaに渡す評価基準 |
|---|---|
| 0：低 | 目的に合わない、または必須条件が満たされない |
| 1：中 | 目的には合いそうだが適用条件が不明。暫定提案 |
| 2：高 | 目的と試験・データ・運用条件が具体的で、適用条件を満たす |

Layaの `score` は、各段階の判定確率から得る0〜2の期待値です。Python側で、0.5未満を「低」、0.5以上1.5未満を「中」、1.5以上を「高」に変換します。この境界値もアプリ側で設定しています。

### Laya以外の処理：推奨度の調整と暫定表示

上記の推奨度に対し、Pythonが次の規則を適用します。

| 条件 | 調整内容 |
|---|---|
| 1回目の4択の上位2候補の `probabilities` の差が0.15未満 | 「高」なら「中」に下げる |
| 最終的に選んだ手法が、1回目の `method.choice` と異なる | 「高」なら「中」に下げる |
| 補足を含む文章が35文字未満で、`explicit_purpose()` でも目的を検出できない | 推奨度を「低」にする |
| オンライン学習を選び、日単位の結果待ちと、分単位・即時の追従要求に相当する文字パターンを検出 | 推奨度を「低」にし、結果の遅れを確認する文を表示 |

最後の規則は「結果／品質」「一週間／数日／翌日／数字＋日」「後」と、「数分／毎分／即時／リアルタイム」などの組み合わせを正規表現で検出します。時間の単位を数値へ変換して比較する仕組みではないため、表現によっては検出できません。

最終推奨度が「高」以外の場合、候補間の差が小さい場合、または最終手法とLayaの直接4択が異なる場合は、「暫定」と表示します。差が小さいかどうかは、最終選定手法にかかわらず、最初の4択の確率分布から計算します。

**推奨度は、Layaの評価をPythonの規則で調整した表示です。正答率・適合率・改善成功確率ではありません。** `confidence` や `answer_confidence` も生出力には含まれますが、このアプリの上記の選定・推奨度調整には使用していません。

### 説明文と、結果を追跡する方法

理由・最初の進め方・適用条件と限界・確認事項は、`METHODS` に手法ごとに記述した定型文を選んで表示します。候補の競合や情報不足などの追加文も、`render()` に記述した定型文です。これらの文章をLayaが生成しているわけではありません。

保存したJSONでは、次の項目から判定の流れを確認できます。

| JSONの項目 | 意味 |
|---|---|
| `model_choice` | 1回目のLayaの直接4択の生出力 |
| `model_intents.update` / `.window` | 1回目のLayaの2つの目的判定の生出力 |
| `method` / `method_id` | Pythonの優先規則を適用した最終手法 |
| `selection_basis` | 最終選定に使った経路。Layaの4択、目的判定のしきい値、または明示目的ルール |
| `model_disagreement` | 最終手法と `model_choice.choice` が異なるか |
| `model_suitability` | 2回目のLayaによる適切さの評価の生出力 |
| `close_candidates` | 最初の4択の上位2候補の差が0.15未満か |
| `insufficient_detail` / `delayed_feedback` | 情報不足・結果の遅れに関するPythonの規則に該当したか |
| `recommendation` / `provisional` | 調整後の推奨度と、暫定表示の有無 |

例えば「プロセスウィンドウを明確化したい」という入力では、Layaが最初に別の手法を選んでも、正規表現ルールが「プロセスウィンドウ」を検出して最終手法を応答曲面法にします。その後、Layaで応答曲面法の適切さを評価します。直接4択と結果が異なれば、推奨度の上限を「中」にして暫定表示します。

このプログラムが行うのは手法の提案です。実験データに対する要因効果の計算、応答曲面の当てはめ、次の具体的な条件の最適化、製造予測モデルのオンライン更新は実装していません。

## 判断基準

| 主目的 | 第一候補 |
|---|---|
| 何が効くか、影響因子の特定と絞り込み | 要因効果分析 |
| 絞った連続因子の関係を近似し、良い条件・合格範囲を説明 | 応答曲面法 |
| 高価な試験やCAEの結果で次の条件を選ぶ、既存知見を使った段階的な探索 | 逐次最適化 |
| 到着する品質実績で予測モデルを継続更新し、摩耗やロット変化へ追従 | オンライン学習 |

4つは重なる概念です。ここでは着手する方法を1つ表示します。過去の知見を活用するだけでオンライン学習にはしません。オンライン学習でモデルを更新するだけでは、運転条件の選択・自動制御は実現しません。

## 限界

汎用モデルの判定を補うため、目的判定と明示ルールを併用しています。否定、複数目的、遠回しな表現の解釈には限界があります。短文や矛盾した条件でも4択のうち1つは表示しますが、推奨度を含め専門家による確認が必要な試作版です。実務での精度は保証していません。運用前には、実際の相談を専門家がラベル付けし、開発用とは別の評価データで手法別の誤分類と推奨度を検証してください。

## Gitで管理しないファイル

`.gitignore` により、仮想環境、モデルのダウンロードキャッシュ、生成された `model_revision.txt`、ログ、ローカルの判定結果、エディター設定などを管理対象から除外しています。モデルとリビジョン記録は、各利用者が `setup.cmd` を実行して作成します。GitHubへの公開やソース配布用のアーカイブにも、`models/` と `model_revision.txt` を含めないでください。判定結果をJSONで保存する場合は、管理対象外の `results/` フォルダーを保存先にすると便利です。
